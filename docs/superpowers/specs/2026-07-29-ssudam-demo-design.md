# 쓰담쓰담 발표용 데모 설계

- 작성일: 2026-07-29
- 상태: 사용자 승인 완료, 구현 계획 작성 전
- 용도: 공모전 및 수업 발표용 프론트엔드 데모

## 1. 서비스 개요

쓰담쓰담은 주민이 길거리 쓰레기를 사진과 위치로 제보하면, 지자체 관리자가 누적된 데이터를 지도와 히트맵으로 확인하고 쓰레기통 설치 후보지를 검토할 수 있는 참여형 매핑 서비스다.

데모의 핵심 가치는 다음과 같다.

- 주민의 제보 절차를 짧고 간단하게 만든다.
- 민원에만 의존하지 않고 위치 기반 데이터를 축적한다.
- 제보 밀집도와 기존 쓰레기통 위치를 함께 분석한다.
- 제한된 예산 안에서 쓰레기통 설치 우선순위를 설명 가능한 형태로 제안한다.

## 2. 목표와 제외 범위

### 목표

- 3~5분 발표 안에 주민 제보부터 관리자 분석까지 한 흐름으로 시연한다.
- 실제 사진 선택, 현재 위치 요청, 지도 직접 위치 선택을 지원한다.
- 주민이 제출한 제보를 관리자 통계, 마커, 히트맵, 추천 위치에 즉시 반영한다.
- 대한민국 전국의 시를 선택할 수 있는 데모 인터페이스를 제공한다.
- 모바일, 태블릿, 데스크톱에서 사용할 수 있는 반응형 화면을 제공한다.
- 서버가 없어도 같은 브라우저에서 안정적으로 시연할 수 있게 한다.

### 제외 범위

- 실제 회원가입, 로그인, 권한 검증
- 서버, 데이터베이스, 클라우드 저장소
- 지자체 내부 결재나 실제 쓰레기통 설치 업무
- 실시간 다중 사용자 동기화
- 실제 민원 시스템 연동
- 운영 환경 수준의 지도·주소 검색 및 지오코딩

## 3. 확정된 제품 결정

- 첫 화면에서 `주민으로 시작`과 `관리자 데모 입장` 중 하나를 선택한다.
- 주민 포털과 관리자 포털은 역할별 독립 화면으로 제공한다.
- 실제 인증 절차는 사용하지 않는다.
- 신고 데이터는 `localStorage`에 저장해 새로고침 후에도 유지한다.
- `데모 데이터 초기화` 기능으로 언제든 초기 상태를 복구할 수 있게 한다.
- 위치 권한을 요청하되, 실패하거나 거부되면 지도에서 직접 위치를 선택할 수 있게 한다.
- 현재 Vite와 TypeScript 구성을 유지한다.
- 지도 렌더링에는 Leaflet을 사용한다.
- 배경 지도에는 사용자가 지정한 `https://mt.google.com/vt/lyrs=m&hl=ko_KR&scale=2&x={x}&y={y}&z={z}` 타일 주소를 사용한다.
- 위 타일 주소가 로딩되지 않을 경우 데이터 레이어를 유지한 채 지도 오류 안내를 표시한다.
- 시각 스타일은 딥 네이비와 선명한 그린을 사용한 공공 서비스형 디자인으로 한다.

## 4. 정보 구조와 경로

해시 기반 경로를 사용해 정적 호스팅에서도 직접 접근과 새로고침이 동작하게 한다.

| 경로 | 화면 | 목적 |
| --- | --- | --- |
| `#/` | 역할 선택 홈 | 서비스 소개와 역할 진입 |
| `#/resident/report` | 주민 제보 | 시, 위치, 사진, 메모 입력 |
| `#/resident/complete/:id` | 제보 완료 | 제보 번호와 관리자 지도 반영 안내 |
| `#/admin` | 관리자 대시보드 | 전국 요약, 지도, 히트맵, 추천 위치 |

알 수 없는 경로는 역할 선택 홈으로 이동한다.

## 5. 화면과 사용자 흐름

### 5.1 역할 선택 홈

- 서비스명과 한 줄 소개를 표시한다.
- `주민으로 시작` 버튼은 주민 제보 화면으로 이동한다.
- `관리자 데모 입장` 버튼은 관리자 대시보드로 이동한다.
- 주민용 진입은 친근하게, 관리자용 진입은 데이터 분석 기능이 명확하게 보이도록 구분한다.

### 5.2 주민 제보

1. 대한민국의 특별시·광역시·특별자치시와 도 산하 시 목록에서 신고 지역을 선택한다.
2. 선택한 시 중심으로 지도를 이동한다.
3. `현재 위치 사용` 또는 지도 클릭으로 정확한 위치를 정한다.
4. 카메라나 파일 선택을 통해 쓰레기 사진을 추가한다.
5. 선택 입력인 짧은 메모를 작성한다.
6. 위치, 시간, 사진을 확인하고 제보를 제출한다.
7. 제출 후 제보 완료 화면으로 이동한다.

필수 항목은 시, 좌표, 사진이다. 메모는 선택 항목이다.

### 5.3 제보 완료

- 화면의 가장 높은 위계로 `제보 완료`를 표시한다.
- 제보 번호를 보여준다.
- `관리자 지도에 반영됨` 안내를 함께 보여준다.
- 히트맵과 쓰레기통 추천 위치가 새 데이터로 갱신된다는 설명을 표시한다.
- `홈으로 돌아가기`와 `다른 제보하기` 행동을 제공한다.

### 5.4 관리자 대시보드

- 상단 요약 지표: 총 제보, 오늘 제보, 집중 관리 지역, 설치 후보 수
- 필터: 대한민국 전체 또는 시, 기간
- 지도 레이어: 개별 제보 마커, 히트맵, 기존 쓰레기통, 추천 위치
- 추천 위치 목록: 추천 점수, 반경 내 제보 수, 기존 쓰레기통까지의 거리
- 제보 또는 추천 위치 선택 시 지도 옆 상세 영역 표시
- 신규 주민 제보가 관리자 화면에 반영됐음을 알아볼 수 있게 최신 제보를 강조
- 데모 데이터 초기화 기능 제공

## 6. 시각 설계

### 색상 방향

- 기본 배경: 밝고 중립적인 회백색
- 주요 색상: 딥 네이비 또는 딥 그린
- 참여·성공 상태: 선명한 그린
- 히트맵: 저밀도 그린, 중밀도 옐로, 고밀도 오렌지·레드
- 오류 상태: 절제된 레드

### 표현 원칙

- 주민 화면은 모바일 우선으로 큰 행동 버튼과 간단한 단계 구조를 사용한다.
- 관리자 화면은 데스크톱 우선으로 지도 면적을 크게 확보한다.
- 지도 위 정보와 카드 정보가 경쟁하지 않도록 관리자 지표 수를 제한한다.
- 색상만으로 상태를 구분하지 않고 라벨, 아이콘, 형태를 함께 사용한다.
- 키보드 포커스, 충분한 명도 대비, 상태 안내 문구를 제공한다.

## 7. 프런트엔드 구조

앱은 다음의 독립된 단위로 나눈다.

### `router`

- 현재 해시를 화면 식별자로 변환한다.
- 화면 전환과 잘못된 경로 복구를 담당한다.
- 저장소나 지도 구현을 직접 알지 않는다.

### `screens`

- `home`: 역할 선택 화면
- `resident-report`: 주민 제보 입력과 검증
- `resident-complete`: 제보 완료 결과
- `admin-dashboard`: 필터, 지도, 통계, 추천 위치

각 화면은 필요한 서비스를 주입받고 다른 화면의 내부 구현에 의존하지 않는다.

### `map`

- Leaflet 초기화, 타일 레이어, 지도 이동, 마커, 히트맵을 관리한다.
- 타일 주소와 Leaflet 세부 설정을 화면에서 분리한다.
- 지도 클릭 좌표를 주민 화면에 전달한다.
- 관리자 화면에서 필터 결과를 데이터 레이어로 표현한다.

### `reports`

- 제보 생성, 검증, 정규화를 담당한다.
- 사진을 저장 가능한 크기로 압축한다.
- 제보 저장소 인터페이스를 통해 데이터를 읽고 쓴다.

### `analytics`

- 제보를 공간 구역으로 묶는다.
- 히트맵 가중치와 추천 후보 점수를 계산한다.
- 화면 코드와 Leaflet 코드에 의존하지 않는다.

### `storage`

- `localStorage` 직렬화와 역직렬화를 담당한다.
- 데이터 버전을 기록한다.
- 저장 데이터가 없으면 초기 샘플을 생성한다.
- 데이터 손상이나 초기화 요청을 안전하게 처리한다.

## 8. 데이터 모델

### 시 목록

```ts
type CityOption = {
  code: string
  name: string
  provinceName: string
  centerLatitude: number
  centerLongitude: number
  defaultZoom: number
}
```

전국 시 목록과 지도 중심 좌표는 앱에 포함된 정적 카탈로그로 관리한다. 데모는 구·군 단위 행정구역 선택이나 좌표 기반 역지오코딩을 수행하지 않는다.

### 제보

```ts
type WasteReport = {
  id: string
  cityCode: string
  cityName: string
  latitude: number
  longitude: number
  createdAt: string
  photoDataUrl: string
  note?: string
  source: 'seed' | 'resident'
}
```

### 기존 쓰레기통

```ts
type ExistingBin = {
  id: string
  cityCode: string
  latitude: number
  longitude: number
}
```

### 추천 위치

```ts
type BinCandidate = {
  id: string
  cityCode: string
  latitude: number
  longitude: number
  score: number
  reportCount: number
  recurrenceScore: number
  nearestBinDistanceMeters: number
}
```

사진은 브라우저 저장 한도를 고려해 최대 가로·세로 1280px 이하로 줄이고 JPEG 또는 WebP로 압축한다.

## 9. 추천 위치 계산

추천 위치 계산은 설명 가능한 데모 알고리즘으로 구현한다.

1. 현재 선택된 시와 기간에 해당하는 제보만 사용한다.
2. 제보를 약 300m 크기의 공간 구역으로 묶는다.
3. 각 구역의 중심 좌표를 후보 위치로 계산한다.
4. 각 후보의 점수를 다음과 같이 계산한다.
   - 제보 밀집도: 70%
   - 반복 제보 정도: 20%
   - 기존 쓰레기통과 떨어진 거리: 10%
5. 서로 500m 이내에 있는 중복 후보는 점수가 높은 하나만 남긴다.
6. 점수가 높은 상위 3개 위치를 제안한다.

관리자에게는 점수만 보여주지 않고 `반경 내 제보 12건`, `기존 쓰레기통까지 640m`와 같은 근거를 함께 표시한다.

이 계산은 실제 도시계획 의사결정을 대체하는 AI 모델이 아니라, 데이터 기반 설치 후보 제안 개념을 설명하는 데모 규칙이다.

## 10. 상태와 데이터 흐름

1. 앱 시작 시 저장소가 버전과 데이터를 읽는다.
2. 저장 데이터가 없으면 전국 샘플 제보와 기존 쓰레기통 데이터를 생성한다.
3. 주민이 제보를 제출하면 검증과 사진 압축 후 저장소에 추가한다.
4. 제보 완료 화면은 저장된 제보 번호와 관리자 지도 반영 상태를 표시한다.
5. 관리자 화면은 저장소에서 최신 데이터를 읽어 필터, 통계, 히트맵, 추천 위치를 계산한다.
6. 데모 초기화는 저장 데이터를 삭제한 뒤 같은 초기 샘플을 다시 생성한다.

한 브라우저 탭에서 역할을 전환하는 것이 기본 시연 경로다. 같은 출처의 다른 탭에서 변경이 발생하면 `storage` 이벤트를 통해 관리자 화면을 갱신할 수 있게 한다.

## 11. 오류 처리

### 위치

- 위치 권한 거부나 API 오류는 제보 흐름을 막지 않는다.
- 선택한 시 중심으로 지도를 이동하고 직접 위치를 선택하도록 안내한다.
- 좌표가 선택되지 않은 상태에서는 제출 버튼을 비활성화한다.

### 사진

- 이미지 파일만 허용한다.
- 읽기 또는 압축 실패 시 파일을 다시 선택할 수 있게 한다.
- 원본 파일은 저장하지 않고 압축 결과만 보관한다.

### 지도

- 타일 실패 시 지도 영역에 오류 안내를 표시한다.
- 이미 계산된 마커, 히트맵, 추천 위치 데이터는 유지한다.
- 사용자가 지도를 다시 불러올 수 있는 행동을 제공한다.

### 저장소

- 저장 공간이 부족하면 사진을 더 낮은 품질로 한 번 재압축한다.
- 다시 실패하면 현재 세션 메모리에서 제보를 유지하고 저장 실패 안내를 표시한다.
- 데이터 구조가 손상되면 임의로 일부만 사용하지 않고 초기화 선택을 안내한다.

### 빈 상태

- 제보가 없는 지역은 `아직 수집된 제보가 없습니다`라고 표시한다.
- 후보가 계산되지 않으면 추천 카드 대신 추가 데이터가 필요하다는 설명을 표시한다.

## 12. 테스트 전략

### 단위 테스트

- 제보 필수값과 좌표 범위 검증
- 사진 압축 결과의 크기 제한
- 저장소 저장, 조회, 버전, 초기화
- 300m 공간 그룹화
- 밀집도, 반복도, 거리 기반 점수
- 500m 이내 후보 중복 제거와 상위 3개 제한

### 통합 테스트

- 주민 제보가 저장되고 완료 화면에 제보 번호가 표시되는 흐름
- 신규 제보가 관리자 통계와 지도 데이터에 포함되는 흐름
- 시와 기간 필터가 통계, 히트맵, 후보 목록에 동일하게 적용되는지 확인
- 위치 권한 거부 후 지도 직접 선택으로 제출할 수 있는지 확인
- 저장 데이터 초기화 후 초기 샘플이 복구되는지 확인

### 화면 검증

- 모바일, 태블릿, 데스크톱 주요 너비 확인
- 지도 타일 실패와 저장 공간 실패 상태 확인
- 키보드로 역할 선택, 입력, 제출, 필터 조작이 가능한지 확인
- 실제 발표 순서대로 처음부터 끝까지 시연

구현은 기능 변경 전에 실패하는 테스트를 작성하고, 해당 테스트를 통과하는 최소 코드부터 추가한다.

## 13. 발표 시나리오

1. 역할 선택 홈에서 서비스 목적을 소개한다.
2. 주민으로 진입해 시, 위치, 사진을 선택하고 제보한다.
3. `제보 완료`와 `관리자 지도에 반영됨`을 보여준다.
4. 홈으로 돌아가 관리자 데모에 입장한다.
5. 신규 제보가 통계와 지도에 반영된 것을 확인한다.
6. 히트맵을 켜 밀집 지역을 설명한다.
7. 추천 위치 카드에서 점수와 추천 근거를 설명한다.
8. 데이터 초기화 버튼으로 다음 시연을 준비한다.

## 14. 완료 기준

- 로그인 없이 두 역할에 진입할 수 있다.
- 주민이 시, 좌표, 사진을 입력해 제보할 수 있다.
- 제보 완료 화면에 `제보 완료`와 `관리자 지도에 반영됨`이 표시된다.
- 새 제보가 관리자 통계, 마커, 히트맵 계산에 포함된다.
- 관리자 화면에서 대한민국 전체와 시 단위 필터를 사용할 수 있다.
- 추천 위치 상위 3개와 각 추천 근거가 표시된다.
- 새로고침 후에도 데이터가 유지된다.
- 데모 데이터 초기화가 동작한다.
- 위치 권한 거부, 지도 타일 실패, 제보가 없는 지역을 처리한다.
- 주요 화면이 모바일과 데스크톱에서 잘리지 않는다.
- 자동화된 단위·통합 테스트와 발표 순서 시연 검증을 통과한다.
