# 쓰담쓰담 Material You UI 전면 재설계

## 1. 목적

현재 쓰담쓰담 데모의 기능과 데이터 흐름은 유지하되, 홈·주민 제보·완료·관리자 화면의 시각 체계와 정보 구조를 전면 재설계한다.

재설계의 목표는 다음과 같다.

- Google Material You의 친근한 톤 표면, 큰 반경, 편안한 여백을 중심에 둔다.
- shadcn/ui의 얇은 경계, 명확한 정보 계층, 절제된 밀도를 관리자 화면에 보조적으로 적용한다.
- 공모전과 수업 발표에서 첫 화면만 보아도 서비스 목적과 핵심 흐름이 이해되게 한다.
- 주민 화면은 쉽고 따뜻하게, 관리자 화면은 정밀하고 신뢰감 있게 표현한다.
- 기존 접근성, 반응형, 저장 복구, 지도 오류, 키보드 조작 기능을 유지한다.

## 2. 승인된 방향

### 2.1 시각 스타일

- 스타일: Material You 중심
- 색상: Forest Sage
- 정보 밀도: 균형형
- 카피: 필수 문구와 기능 의미는 유지하되 제목, 설명, 버튼 문구, 정보 순서는 간결하게 정리한다.

### 2.2 제품 분위기

친근하지만 장난스럽지 않은 공공 환경 서비스로 표현한다.

- 넓은 배경은 매우 밝은 세이지 톤을 사용한다.
- 핵심 CTA와 선택 상태에만 짙은 포레스트 색상을 사용한다.
- 주요 콘텐츠는 흰색 또는 옅은 톤 표면에 배치한다.
- 장식보다 정보 계층, 간격, 일관된 형태로 완성도를 만든다.
- 과도한 그라디언트, 과도한 그림자, 여러 종류의 카드 색상은 사용하지 않는다.

## 3. 기술 방향

프로젝트는 Vanilla TypeScript와 DOM 렌더링 구조를 유지한다. React 전용 shadcn/ui 패키지는 도입하지 않는다. 대신 shadcn/ui의 시각 원칙을 CSS 토큰과 공통 클래스에 반영한다.

### 3.1 변경 범위

- `src/style.css`: 전역 디자인 토큰과 공통 컴포넌트 상태
- `src/screens/home/home.ts`, `home.css`: 홈 정보 구조와 시각 표현
- `src/screens/resident/report.ts`, `complete.ts`, `resident.css`: 제보와 완료 화면
- `src/screens/admin/dashboard.ts`, `admin.css`: 관리자 대시보드
- 필요 시 코드 기반 인라인 SVG 아이콘 모듈 추가
- 필요 시 시각 회귀용 Playwright 테스트와 스크린샷 추가

### 3.2 유지 범위

다음 기능과 공개 동작은 변경하지 않는다.

- 해시 라우팅과 역할별 진입
- 전국 시 카탈로그
- 주민 위치 선택, 사진 압축, 메모, 제출
- `제보 완료`와 `관리자 지도에 반영됨`
- 저장소, 손상 데이터 복구, 세션 전용 경고
- Leaflet 지도와 지정된 Google 타일 URL
  `https://mt.google.com/vt/lyrs=m&hl=ko_KR&scale=2&x={x}&y={y}&z={z}`
- 히트맵, 쓰레기통, 추천 위치, 마커 상세
- 300m 그룹, 70/20/10 점수, 500m 중복 제거
- 키보드 위치 선택, 지도 재시도, 다이얼로그 초점 복귀

## 4. 디자인 시스템

### 4.1 색상 토큰

최종 구현에서 명도 대비를 검증하며 다음 계열을 기준으로 사용한다.

| 역할 | 기준 색상 | 용도 |
|---|---:|---|
| Primary | `#225F4D` | 핵심 CTA, 활성 상태, 주요 숫자 카드 |
| Primary Hover | `#184C3C` | CTA hover/pressed |
| Secondary | `#397763` | 보조 강조, 링크, 아이콘 |
| Primary Container | `#DCEFE4` | 톤 버튼, 선택 칩, 보조 표면 |
| Canvas | `#F5F8F3` | 전체 페이지 배경 |
| Surface | `#FFFFFF` | 카드, 폼, 패널 |
| Surface Variant | `#EDF3EF` | 약한 구획, 비활성 표면 |
| Ink | `#18372D` | 주요 텍스트 |
| Muted | `#69756F` | 설명, 메타데이터 |
| Outline | `#DFE7E2` | 경계선 |
| Error | `#B3261E` | 오류 텍스트와 상태 |
| Error Container | `#F9DEDC` | 오류 배너 |
| Warning Container | `#FFF1C2` | 저장·타일 경고 |

색상만으로 상태를 구분하지 않으며 아이콘과 텍스트를 함께 제공한다.

### 4.2 타이포그래피

- 기본 글꼴: Pretendard, Noto Sans KR, system-ui
- Display: 홈 핵심 문장에만 사용, 굵기 800 이상, 짧은 두 줄
- Headline: 화면 제목, 카드 섹션 제목
- Title: 카드·패널 제목
- Body: 설명과 입력 안내
- Label: 버튼, 칩, 필터, 짧은 메타데이터
- 숫자 KPI는 탭형 숫자를 사용하고 자간을 좁혀 안정적인 정렬을 만든다.

### 4.3 형태와 간격

- 큰 화면 표면: 24–28px 반경
- 카드·패널: 16–20px 반경
- 입력·작은 컨트롤: 12–14px 반경
- CTA·필터 칩: pill 형태
- 공통 간격 단위: 4, 8, 12, 16, 24, 32, 48px
- 주요 콘텐츠 최대 폭: 홈 1200px, 주민 840px, 관리자 1480px
- 그림자는 한 종류의 매우 부드러운 저고도 그림자를 기본으로 사용한다.

### 4.4 공통 컴포넌트

- 상단 앱바
- Filled 버튼
- Tonal 버튼
- Text 버튼
- 입력·선택·텍스트 영역
- 필터 칩과 토글 칩
- KPI 카드
- 정보 카드와 상세 패널
- 상태 배너
- 성공 상태 패널
- 확인 다이얼로그
- 코드 기반 SVG 아이콘

모든 상호작용 요소의 최소 높이는 44px로 한다.

## 5. 화면별 설계

### 5.1 홈

정보 순서는 다음과 같다.

1. 간결한 워드마크와 환경 아이콘
2. `발견하고, 함께 바꿔요.` 형태의 짧은 핵심 문장
3. 사진·위치 제보와 데이터 개선을 설명하는 한 문단
4. 가장 강한 `주민으로 시작하기` CTA
5. 톤 표면의 `관리자 데모` 진입 카드
6. 위치 기반 제보, 도시별 히트맵, 데이터 기반 추천의 세 가치

홈은 장식용 대형 카드 안에 다시 페이지를 넣지 않는다. 페이지 전체 캔버스와 콘텐츠 블록을 직접 구성한다.

### 5.2 주민 제보

- 상단 앱바에 홈 이동, 워드마크, 현재 화면 정보를 배치한다.
- 큰 제목과 한 문장 안내 아래에 진행감을 주는 얇은 단계 표시를 둔다.
- 폼 입력은 하나의 긴 흰 카드가 아니라 논리적 구역별 표면으로 나눈다.
- 지역 선택, 위치, 사진, 메모 순서를 유지한다.
- 현재 위치와 선택 지역 중심 버튼은 톤 버튼으로 표현한다.
- 지도는 넓은 둥근 표면으로 배치하고 지도 상태와 선택 좌표를 시각적으로 분리한다.
- 사진 선택 후 미리보기는 이미지 비율을 유지하며 과도하게 커지지 않게 한다.
- 제출 버튼은 화면의 유일한 Filled CTA로 유지한다.
- 모바일에서 CTA가 화면 하단에 자연스럽게 도달하도록 여백을 충분히 둔다.

현재 기능은 단일 폼 제출을 유지한다. 단계 표시는 별도 라우트나 다단계 마법사를 만들지 않는다.

### 5.3 제보 완료

- 성공 아이콘, `제보 완료`, 접수 설명을 가장 높은 계층에 둔다.
- 제보 번호는 복사 가능한 정보 행처럼 명확하게 표시한다.
- `관리자 지도에 반영됨`을 옅은 Primary Container 상태 패널에 표시한다.
- 세션 전용 저장 경고는 성공 패널과 구분되는 Warning Container를 사용한다.
- `홈으로 돌아가기`를 Filled 버튼, `다른 제보하기`를 Tonal 버튼으로 구분한다.

### 5.4 관리자 대시보드

데스크톱 정보 순서는 다음과 같다.

1. 상단 앱바: 홈 이동, 워드마크, 초기화
2. 제목과 짧은 설명
3. KPI 4개
4. 지역·기간 필터와 레이어 칩
5. 지도
6. 추천 위치, 선택한 제보/후보 상세, 레이어 상태 패널

세부 규칙:

- KPI는 같은 흰 표면을 기본으로 하고 첫 번째 핵심 카드만 Primary 색상을 사용한다.
- 필터는 compact select와 pill 토글을 조합한다.
- 지도와 상세 패널은 데스크톱에서 약 2:1 비율로 배치한다.
- 추천 카드 전체가 선택 가능하되 실제 버튼 의미와 키보드 조작을 유지한다.
- 점수 근거는 막대와 숫자를 함께 사용한다.
- 선택한 제보와 후보 상세는 같은 패널에서 상태에 따라 내용을 교체한다.
- 초기화는 상단의 낮은 강조 버튼으로 두고 다이얼로그 안에서만 위험 색상을 사용한다.

## 6. 반응형 설계

### 데스크톱: 1200px 이상

- 홈 콘텐츠와 관리자 지도·상세를 넓게 표시한다.
- 관리자 지도와 상세 패널을 두 열로 유지한다.

### 태블릿: 768–1199px

- KPI는 2×2 그리드로 변경한다.
- 지도 아래에 상세 패널을 배치한다.
- 필터는 두 줄까지 허용한다.

### 모바일: 360–767px

- 모든 화면을 한 열로 구성한다.
- 페이지 패딩은 16px을 기준으로 한다.
- KPI는 2열을 유지하되 작은 화면에서 내용이 잘리면 1열로 전환한다.
- 지도 높이는 320–380px 범위로 유지한다.
- 버튼과 필터는 44px 이상 터치 영역을 제공한다.
- 필수 컨트롤을 숨기지 않는다.

## 7. 상태와 상호작용

- hover: 경계색과 배경 톤을 조정하고 이동은 최대 1–2px로 제한한다.
- pressed: 1px 축소 또는 더 짙은 톤으로 표현한다.
- focus-visible: Primary 계열의 3px 링과 충분한 offset을 제공한다.
- loading: 버튼 텍스트와 진행 아이콘을 함께 표시한다.
- disabled: 불투명도만 낮추지 않고 커서와 명도도 조정한다.
- error: 필드 하단 오류와 Error Container 배너를 사용한다.
- warning: Warning Container와 바로 실행할 수 있는 복구 버튼을 제공한다.
- success: Primary Container와 체크 아이콘을 사용한다.
- 전환 시간: 160–220ms
- `prefers-reduced-motion: reduce`에서 장식 전환과 이동 효과를 제거한다.

## 8. 카피 원칙

- 한 문장은 가능한 한 30자 내외로 작성한다.
- 사용자가 해야 할 행동을 먼저 쓴다.
- 같은 의미의 `지역`과 `시` 표현을 화면별로 혼용하지 않는다.
- 기술 용어보다 주민이 이해하기 쉬운 표현을 사용한다.
- 필수 문구 `제보 완료`, `관리자 지도에 반영됨`, `지도 다시 불러오기`는 유지한다.

## 9. 오류·복구 상태

- 저장 데이터 손상: 상단 상태 배너와 `손상된 데이터 초기화` 버튼
- 세션 전용 제보: 완료 화면의 별도 경고 배너
- 지도 타일 실패: 선택 좌표와 분리된 상태 배너와 재시도 버튼
- 사진 처리 실패: 사진 구역 안의 오류 문구와 다시 선택 안내
- 위치 권한 거부: 지도 선택과 키보드 기반 지역 중심 선택 안내
- 데이터 없음: 관리자 지도와 상세 패널을 제거하지 않고 빈 상태 문구 제공

## 10. 접근성

- 의미 있는 버튼, label, fieldset, dialog 구조를 유지한다.
- 아이콘 단독 버튼에는 접근 가능한 이름을 제공한다.
- 색상 대비는 WCAG AA를 목표로 검증한다.
- 키보드 순서는 화면의 시각 순서와 일치시킨다.
- 오류와 상태 변경은 필요한 위치에 `aria-live`로 전달한다.
- 지도 대체 위치 선택 기능을 유지한다.
- 다이얼로그 종료 후 트리거로 초점을 복귀한다.

## 11. 검증 전략

기존 기능 테스트를 모두 유지한다.

- Vitest 단위 테스트 87개 이상
- Playwright E2E 10개 이상
- TypeScript/Vite 프로덕션 빌드
- 360×800, 768×1024, 1440×900 가로 오버플로 검사
- 주민 제보에서 관리자 반영까지 발표 흐름
- 키보드 위치 선택과 폼 제출
- 지도 타일 실패와 재시도
- 관리자 필터, 레이어, 마커 상세, 초기화
- reduced motion

시각 검증을 추가한다.

- 홈, 주민 제보, 완료, 관리자 화면의 데스크톱 스크린샷
- 홈, 주민 제보, 관리자 화면의 모바일 스크린샷
- 문구 잘림, 겹침, 과도한 스크롤, 빈 공간 불균형 확인
- 지도 위 UI와 Leaflet 컨트롤이 새 디자인 토큰과 충돌하지 않는지 확인

## 12. 완료 기준

- 모든 화면이 Forest Sage Material You 디자인 시스템으로 통일된다.
- 홈에서 주민과 관리자 진입 우선순위가 즉시 이해된다.
- 주민 제보 흐름에서 각 입력의 의미와 다음 행동이 명확하다.
- 관리자 화면에서 KPI, 필터, 지도, 추천 근거의 계층이 명확하다.
- 360px부터 1440px까지 가로 스크롤과 문구 잘림이 없다.
- 기존 87개 이상 단위 테스트와 10개 이상 E2E가 통과한다.
- 프로덕션 빌드가 통과한다.
- `main`에 커밋하고 `origin/main`으로 일반 push한다.
